# hunafazaky.github.io

Portfolio frontend. React Router v8 in **SPA mode** (static output, no
Node server) — see `react-router.config.ts`. Deployed to GitHub Pages.
Companion repos: `portfolio-backend` (the Go API this fetches data from
and, for the dashboard, writes to).

## Why SPA mode, and why the site never calls the live API

Render's free tier sleeps after inactivity — unacceptable cold-start
latency for visitors. So:

- **Public site**: built entirely from static JSON (`app/data/*.json`),
  generated by `scripts/fetch-data.mjs` _before_ every build. Visitors
  never make a live API call. In dev (`bun dev`) the same code calls the
  live API directly instead — see `app/lib/data.ts`.
- **Dashboard** (`/dashboard/*`): always live, `credentials: 'include'` on
  every request — it's the one place real-time data actually matters, and
  the only place a human (you) occasionally waits on a cold start.
- **Rebuild loop**: `.github/workflows/deploy.yaml` runs on both `push`
  and `repository_dispatch` (fired by the backend after a successful admin
  save) — same job either way: fetch → build → deploy.
- **Exception**: the contact form (`components/sections/Contact.tsx`)
  always hits the live API too, since it's a write. It's the one visitor
  interaction where a cold Render instance could add real delay — worth
  knowing about, no workaround built in yet.

Full rationale: `portfolio-frontend-context.md` (in the original planning
thread) and `portfolio-backend/README.md`'s "Architecture note" section.

## Setup

```bash
cp .env.example .env    # set VITE_API_URL to your local/deployed API
bun install
bun dev
```

In CI, set `VITE_API_URL` as a repo **variable** (not secret — it's a
public URL) under Settings → Secrets and variables → Actions → Variables.

## What's built vs. stubbed

**Built and working:** the public single-page site (all sections — Hero,
Summary, Experience, Project, Education, Skills, Certificates, Contact),
dark/light theme (Nord palette, defaults dark), ID/EN language switching,
the dashboard's auth guard + login + overview (with real stat counts from
the API).

**Stubbed (next phase):** the actual CRUD forms for
`/dashboard/{profile,experiences,projects,education,skills,certificates,messages}`
— each currently renders a placeholder. The backend endpoints they'll call
already exist and are documented at the API's `/api/docs`.

## Known gaps / things to double check

- `bun.lock` was **removed** — the reference scaffold's lockfile no longer
  matches this `package.json` (dependencies changed: dropped
  `@react-router/serve`/`@react-router/node`, added `heroicons`, `motion`,
  `i18next`/`react-i18next`). Run `bun install` once to generate a fresh
  one before committing.
- **Not build-verified.** This was written in a sandbox without a JS
  package registry or bun/node runtime available, so `bun install` /
  `bun run build` / `bun run typecheck` have not actually been run. Please
  run all three before trusting this compiles — dependency versions in
  `package.json` are best-effort and `bun install` will resolve them for
  real.
- `Skill.tsx` resolves `icon_key` against the full `@heroicons/react/24/outline`
  export object at runtime — fine for a small skill list, but means the
  whole icon set ships in the bundle rather than being tree-shaken. Worth
  revisiting if bundle size matters.
